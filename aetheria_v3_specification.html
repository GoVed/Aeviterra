3. Detailed Subsystem Architecture

3.1. Proof-of-Physical-Capacity (PoPC) & Verifiable Shard Shuffling

Aetheria V3 eliminates the fatal vulnerability of "local player consensus" (F01, F02). In V3, players in a spatial chunk are strictly clients. They do not validate their own chunk. Instead:

  1. Bonded Validator Pool: Independent node operators deposit hardware commitments (continuous Verifiable Delay Functions and Proof-of-Spacetime storage allocations) to join the global validator candidate set.
  2. Verifiable Shard Committee Assignment: For spatial chunk C = (x, y, z) and committee epoch E, the authoritative consensus committee of size n = 3f + 1 is selected deterministically:
    Committee(C, E) = Sample( ValidatorPool, H(ThresholdBeacon(E) || C) )
    Because the threshold beacon output cannot be predicted prior to epoch transition, attackers cannot pre-target or stack a specific spatial shard.
  3. HotStuff-Variant Shard BFT: Consensus proceeds through three explicit phases: Prepare, Pre-commit, and Commit. A commit certificate Q requires ≥ 2f + 1 unique validator signatures. Validators must durably persist their vote to disk (WAL) before transmitting, preventing equivocation across crashes.

3.2. Leased State Enclaves & Single-Use Settlement Nullifiers

To allow players to explore uninhabited wilderness or play in unobserved offline mode without risking double-spending (the "Multiverse Fork" exploit F03), Aetheria V3 introduces the Leased State Enclave Protocol:

  1. State Lease Grant: Before entering unobserved space, the avatar checks out an exclusive lease from the shard committee. The committee locks the avatar's state in the Sparse Merkle Tree (SMT) and issues a StateLease:
    LeaseID = H(ActorID || Rstart || Tickgrant || Salt)
    The lease binds a bounded tick horizon (e.g. ≤ 3,600 ticks = 1 hour) and an initial entropy seed Sentropy emitted by the network's threshold beacon.
  2. Deterministic Offline Execution: The client executes the Wasm/zkVM kernel (RISC-V guest: SP1 / RISC Zero). Random rolls are derived via PRF from H(Sentropy || step). Actions form an unbroken sequential cryptographic hash chain:
    C0 = LeaseID,     Ci = H(Ci−1 || Actioni)
    The player cannot grind random drops because they do not control the PRF seed.
  3. Settlement & Atomic Nullification: Upon reconnecting, the player presents a zk-STARK proof certifying execution validity, the final state root Rend, and the single-use settlement nullifier:
    N = H(LeaseID || Rend || "NULLIFIER")
    The shard committee verifies that: (a) LeaseID is active and not expired; (b) N ∉ ConsumedNullifiers; (c) the zk proof verifies the canonical guest program hash. If valid, N is added to the consumed set, the lease is burned, and Rend is merged into canonical history.
    Double-Spend Defense: If an attacker forks two offline timelines A and B from the same lease, only the first to submit succeeds. The second is rejected with LeaseAlreadySpent or NullifierAlreadyConsumed.
  4. Reclamation on Disconnect: If the player fails to check in before the tick horizon expires, the committee executes a deterministic lease reclamation transition, reverting the avatar to its pre-lease state.

3.3. Dynamic Swept-Volume Halos & Asynchronous 2PC with Compensating Abort

To solve boundary seam tunneling (F11) and cross-shard lock stranding (F12):

  • Dynamic Swept Margin: The boundary margin around every chunk dynamically adapts to physical limits:
    Rhalo = Rinteract + vmax · Δtrollback + ½ amax · (Δtrollback)2 + εnumerical
    Every fast projectile (e.g., 100 m/s arrows) declares a continuous bounding swept capsule AABB(t0 → t1). The protocol identifies all intersecting chunks and registers the interaction across all relevant boundaries.
  • Non-Blocking 2-Phase Commit (ABFT-2PC):
    1. Declare: Shard A locks the entity and records DeclareTx(tx_id, dst: Shard_B, expiry_tick: T + 50).
    2. Prepare: Shard B verifies expected version and records PrepareTx.
    3. Commit / Compensating Abort: If Shard B commits before expiry, the transaction finalizes. If Shard B stalls or the network partitions, once current_tick >= expiry_tick, Shard A automatically executes an Abort-Compensation state transition. The local entity is unlocked without requiring coordinator response. Lock stranding is mathematically impossible.

3.4. Irrevocable Commit-Before-Entropy Randomness Pipeline

Pairwise commit-reveal (Gemini v1.0) suffers from selective abort (F05): the last revealer computes the outcome first and drops connection if they take damage. In Aetheria V3:

  1. Phase 1 (Irrevocable Action Commitment): When an avatar executes a probabilistic action (combat strike, critical roll) at tick T, the intent is committed into the block. Action costs (stamina, ammo, tool wear) are debited immediately, and a future threshold beacon round Rtarget = Rcurrent + ΔR is assigned.
  2. Phase 2 (Deterministic Resolution): When the threshold committee emits the BLS signature σR for round Rtarget, the outcome entropy is computed as:
    Eevent = H("AETHERIA_EVENT_RNG_V1" || action_id || σR)
    The outcome is evaluated using rejection-free fixed-integer scaling. Because the cost was already debited, player disconnects do not halt resolution. The committee deterministically resolves the outcome regardless of player presence.

3.5. Pure Semantic Generative Asset Grammar

ChatGPT proved that user-uploaded 3D meshes (even capped at 2,048 vertices) and 128x128 textures allow multi-kilobyte steganographic covert channels (F19) and expose node operators to file-carrier legal liabilities (F20).

Architectural Paradigm: Zero User Media on Consensus
Aetheria V3 eliminates all binary file uploads. World structures and equipment exist on consensus exclusively as Semantic Generative Tokens:

- Structural Walls: StructuralPrimitive { style: FortifiedCitadel, material: Granite, length: 20, height: 10, thickness: 2, features: 0b101 } (48 bytes).
- Heraldic Crests: HeraldryToken { primary_field: Azure, charge: LionRampant, charge_color: Or } (8 bytes).
- Equipment: EquipmentGrammar { item_class_id: Broadsword, primary_material: DamascusSteel, mass_grams: 1400 } (32 bytes).

Client-Side Procedural Synthesis: The client's rendering engine generates photorealistic 3D geometry and PBR procedural shader graphs locally from these strongly typed tokens. Steganographic capacity is reduced to zero, storage drops by 99.99%, and node operators face zero media liability.

3.6. Strict Q64.64 Deterministic Mathematics & Sandboxing

To eliminate cross-architecture floating-point divergence (F13, F14):

  • Representation: Signed 128-bit integer X ∈ [−2127, 2127 − 1] with scaling factor 264.
  • Multiplication: Exact 256-bit intermediate product P = X × Y, followed by normative truncation toward zero: trunc(P / 264). Overflow is detected and rejected atomically.
  • Division: Exact 256-bit binary long division with checked division-by-zero rejection.
  • Square Root: Exact 256-bit bit-search integer square root: ⌊ √(X · 264) ⌋.
  • Wasm Sandboxing: The Wasm bytecode validator strips all f32/f64 floating-point opcodes. The sandbox enforces a 50M instruction fuel limit, 64MB linear memory ceiling, and sorted BTreeMap entity iteration.

5. Century-Scale Longevity, Governance & Cryptographic Agility

Gemini's Kelvin 0K code freeze was fatal because it prevented repairing arithmetic bugs or upgrading cryptographic algorithms. Over a century-long horizon, classical algorithms such as Ed25519 and SHA-256 will inevitably face cryptanalytic obsolescence or quantum degradation.

Formalized Protocol Epoch Gates (FPEG):

  • Mathematical Invariance: The fundamental physical conservation laws, coordinate spaces, and state transition semantics are immutable.
  • Crypto-Agile Modular Suites: Cryptographic primitives are versioned through discrete protocol epochs. Epoch N can introduce Post-Quantum signatures (ML-DSA / Dilithium) and zk-friendly hash functions (Poseidon / BLAKE3) via a 6-month pre-announcement and supermajority consensus vote.
  • Recursive zk-SNARK State Migration: When migrating between cryptographic epochs, historical state roots from epoch N − 1 are attested using recursive zk-SNARK state migration circuits. Historical lineage remains verifiable without relying on obsolete or compromised keys.
  • Weak Subjectivity Checkpoint Pinning: Long-offline clients synchronize against authenticated multi-signed epoch checkpoints rather than unbounded historical block replay, defeating long-range attacks (F28).
